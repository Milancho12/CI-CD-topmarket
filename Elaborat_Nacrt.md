## 1. Вовед
Овој елаборат го опишува процесот на докеризација, автоматизација и оркестрација на full-stack веб апликација за менаџмент и дистрибуција (TopMarket). Преку овој проект се демонстрираат клучните концепти од предметот Континуирана интеграција и испорака.
Фокусот е ставен на контејнеризација на микросервисната архитектура, автоматизација на процесот за градење и дистрибуција на Docker имиџи преку GitHub Actions, како и оркестрација на целиот систем користејќи Kubernetes.

## 2. Опис на апликацијата
Апликацијата „TopMarket“ претставува систем за менаџирање на дистрибуција на леб и печива. Архитектурата на системот се состои од четири главни компоненти:
- **Backend апликација:** Развиена во Node.js (Express), служи како REST API кое ја содржи бизнис логиката и комуницира со базата на податоци.
- **Frontend апликација:** Развиена со Node.js и EJS (Embedded JavaScript templates), која служи како кориснички интерфејс преку кој возачите и администраторите комуницираат со системот.
- **Worker сервис:** Сервис базиран на Node.js и Puppeteer кој служи за автоматизирано прибирање податоци (веб скрејпинг) од надворешни системи и нивно процесирање.
- **База на податоци:** PostgreSQL релациона база која се користи за перзистенција на сите податоци во системот.

## 4. Докеризација на апликацијата
За секоја од компонентите (Backend, Frontend и Worker) се креирани посебни `Dockerfile` фајлови. 
- За **Frontend** и **Backend** сервисите се користи лесен `node:20-alpine` имиџ, каде се инсталираат потребните зависности (`npm install`) и се изложуваат соодветните порти.
- За **Worker** сервисот се користи специјализиран `ghcr.io/puppeteer/puppeteer:21.9.0` имиџ кој веќе содржи прединсталиран Chromium прелистувач неопходен за веб скрејпингот. Дополнително е оптимизиран процесот на инсталација на пакетите со игнорирање на повторното преземање на Chromium (`--ignore-scripts`).

## 5. Оркестрација со Docker Compose
За локално подигнување и поврзување на сите сервиси се користи `docker-compose.yml` конфигурација. Дефинирани се четири сервиси:
- **db:** Користи официјален `postgres:16-alpine` имиџ. Податоците се перзистираат преку Docker volume (`pgdata`), а дефиниран е и `healthcheck` механизам за да се осигура дека базата е спремна пред да се покренат останатите сервиси.
- **backend:** Зависен е од `db` сервисот и комуницира преку внатрешната мрежа.
- **frontend:** Зависен е од `backend` и е изложен на порта 3005 на локалната машина за надворешен пристап.
- **worker:** Зависен е од базата и ги содржи потребните конфигурации за proxy и Puppeteer извршување.

## 6. CI/CD решение со GitHub Actions
Во проектот е имплементирано CI (Continuous Integration) решение користејќи GitHub Actions. Целта е автоматизација на процесот на градење (build) и дистрибуција при секоја нова промена на кодот.
Креиран е `.github/workflows/ci.yml` кој се активира при секој `push` на `main` гранката. Workflow-от ги извршува следните чекори:
- Го презема изворниот код.
- Се најавува на Docker Hub користејќи GitHub Secrets (`DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN`).
- Ги гради Docker имиџите за frontend, backend и worker користејќи ги официјалните Docker Buildx акции.
- Автоматски ги прикачува (push) новите имиџи на Docker Hub профилот.

Откако градењето и прикачувањето на имиџите ќе заврши успешно, се активира втората фаза (Continuous Deployment) преку дополнителен `deploy` job. 
Овој чекор се поврзува со продукцискиот сервер користејќи SSH (со помош на `appleboy/ssh-action` и `appleboy/scp-action`). 
Тој автоматски го копира `docker-compose.yml` фајлот на серверот, ги повлекува новите имиџи (`docker-compose pull`) и ја рестартира апликацијата во позадина. На овој начин се постигнува целосна автоматизација на животниот циклус – од пишување код до продукциско деплоирање.

## 7. Kubernetes Оркестрација
За продукциско деплоирање и управување со скалабилноста, проектот е деплоиран во локална Kubernetes околина. Сите манифести се организирани во `k8s/` фолдерот.

- **Namespace:** Креиран е посебен изолиран простор `topmarket-namespace` за сите ресурси на апликацијата.
- **ConfigMap и Secrets:** Сите несензитивни environment променливи се сместени во ConfigMap, додека лозинките и URL-адресите на базата се безбедно сместени во Secret.
- **StatefulSet за Базата:** PostgreSQL базата е подигната преку `StatefulSet` за да се обезбеди перзистенција и стабилност на податоците, поврзана со соодветен `Service`.
- **Deployments:** За frontend, backend и worker сервисите се креирани `Deployment` ресурси кои ги влечат соодветните имиџи од Docker Hub. 
- **Ingress:** Пристапот до frontend апликацијата од надворешниот свет е овозможен преку `Ingress` ресурс кој го рутира сообраќајот кон frontend сервисот преку доменот `topmarket.local`.

## 8. Заклучок
Со реализацијата на овој проект е изработен систем кој ги опфаќа сите фази на современиот развој на софтвер – од локална контејнеризација, автоматизација на градењето, до деплоирање во кластер. Користењето на Docker Compose значително го олеснува локалниот развој, додека GitHub Actions овозможува континуирана интеграција без мануелна интервенција. На крајот, оркестрацијата со Kubernetes обезбедува стабилна и скалабилна архитектура, нудејќи практична примена на DevOps принципите.
